# HAMLET Mobile

Native Android and iOS application for HAMLET, built with Expo SDK 58, React Native 0.88, TypeScript and Expo Router.

## Product direction

One app with role-aware experiences for guests, owners, property managers and agents. Horatio will be integrated as the assistant layer after the core guest and partner journeys are connected.

## Local setup

1. Install Node.js 22.13 or newer.
2. Copy `.env.example` to `.env` and provide the existing HAMLET Supabase project URL, publishable key and API origin.
3. Run `npm install`.
4. Run `npx expo install --fix` to align SDK-managed dependencies.
5. Run `npx expo-doctor`.
6. Run `npx expo start`.

## Native authentication callback setup

The app uses the custom URL scheme `hamlet://auth/callback` for email confirmation and password recovery. Add that exact URL to the Supabase project's Authentication URL Configuration > Redirect URLs before testing email confirmation on a device. Also add the Expo development callback URL generated by `npx expo start` when testing in Expo Go or a development client. Do not add broad wildcard production redirects.

Google and Apple native OAuth are not yet wired. The existing web OAuth callback must not be assumed to work with the native scheme.

## Backend integration rules

- Reuse the existing HAMLET Supabase project, schema, RLS policies and server-side API routes.
- Do not create a second database or duplicate the web application's data model.
- Never trust client-submitted prices, fees, booking states or payment status.
- Use the existing central pricing and quote contract on the server.
- A booking request is not a confirmed booking.
- Only verified payment-provider webhooks may confirm payment.
- Keep refundable caution deposits separate from accommodation revenue and partner allocations.
- Respect owner-authorised property access and server-enforced role permissions.
- Never expose private guest identity records to owners or agents by default.
- Only `EXPO_PUBLIC_` values belong in the mobile bundle. Never add service-role or payment-provider secret keys.

## Current implementation status

Implemented in this branch:
- Expo project configuration, navigation shell and HAMLET visual foundation.
- Guest discovery and approved property catalogue.
- Sanitised public API endpoints for approved stays and property detail.
- Native email/password sign-in, guest registration with name/phone metadata and password reset request.
- Native auth deep-link callback, email confirmation and password update flow.
- Supabase session persistence using AsyncStorage.
- Property detail view, native Android/iOS date picker, guest count and special requests.
- Guest booking request submission through the existing server-authoritative `/api/booking-requests` endpoint.
- Guest booking history and cancellation through the existing `transition_booking` RPC.

Booking requests remain requests: the property partner must confirm availability before payment opens. No payment is captured in this milestone.

Still to implement and test: profile editing, payment handoff, owner/agent workspaces, partner deal board, caution-fee inspection flow, push notifications, Horatio, Google/Apple sign-in, app icon/splash screen and end-to-end physical-device QA.

The current production marketplace geography is Lagos-only; Abuja and Ibadan are shown as coming later until the backend geography guard is expanded.
